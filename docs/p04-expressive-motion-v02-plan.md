# P04 Expressive Motion v0.2 — implementation plan

Status: approved choreography blueprint; v0.2 implementation and QA are recorded in [the implementation report](p04-expressive-motion-v02-implementation-report.md). Prototype 04 — Modern Editorial Harmony remains the approved production visual baseline.

## Direction and implementation contract

Editorial stillness → controlled reveal → precise response → rest. The entrances should be plainly visible, with the longest major reveals about 700–1200ms and section-specific travel about 30–80px on desktop. These are local choices, not global defaults. Once an element arrives, its transform, clip, and opacity return to the unchanged P04 resting state. No looping or scroll-linked movement.

The current M1 foundation has visible HTML by default, one reveal IntersectionObserver, two navigation observers, a `motion-ready` gate, one-time pending targets, fail-open initialization, focus resolution, live reduced-motion handling, and a single native photo dialog. Extend those pieces with P04-scoped motion roles and CSS custom properties. Keep the existing six-link navigation mapping, native anchors, in-flow mobile menu, image assets, grid geometry, and content order. Do not add a library, framework, RAF loop, scroll hijack, or extra runtime dependency.

**Reveal rules:** Only arm targets below the initial viewport after the observer has been installed successfully. Give the early Hero a finite entrance only during a prompt top-of-page load; late scripts, deep links, restored pages, and focused targets remain immediately visible. Define each section's role, axis, distance, duration, and delay declaratively in P04 CSS/HTML; the observer only changes state. A section may coordinate nearby layers, but a tall section's later photo or list must remain independently observable. Avoid nested hidden parent and child states that can strand content. Preparation has no transition; each target unobserves after arrival. Focusing content, a failed observer, `pageshow` restoration, print, or a live switch to reduced motion resolves pending content immediately.

**Shared easings:** `arrival` = `cubic-bezier(.16,1,.3,1)` for long editorial travel; `glide` = `cubic-bezier(.22,.61,.36,1)` for clipped photo surfaces; `response` = `cubic-bezier(.2,0,0,1)` for controls. Finite opacity can accompany movement, but opacity alone should not carry the major section reveal. These values can be tuned after browser review without changing the layout.

## 10. Button, link, and image response

Use hover only with `(hover: hover) and (pointer: fine)` and mirror meaningful feedback at `:focus-visible`. Button surface/color changes take 180–240ms `response`; arrow moves 4–6px horizontally and returns at rest. Link underline draws from the text's leading edge over about 220ms; active navigation remains indicated without hover. A photo's image may scale to at most 1.02 inside the already clipped frame over 300–360ms, with no card lift or layout change. The overlay photo button keeps its visible focus ring. Touch gets press/focus feedback without hover zoom. Reduced motion removes arrow translation, underline draw, and photo scaling; color and focus indications remain immediate and clear.

## 11. Lightbox

Keep the current single native `<dialog>`, ten eligible photographs, semantic overlay buttons, Escape/backdrop/close behavior, focus return, body scroll restoration, and responsive source selection. Opening is a user-triggered modal event: backdrop opacity settles over 220–260ms, image moves from 20px below with 0.98→1 scale over 320–380ms `glide`, and close control is available as soon as `showModal()` succeeds. Exit uses ≤160ms and a bounded timeout independent of transition completion. The image stays within existing viewport caps. On mobile, use 10px travel and ≤280ms. Reduced motion makes open and close immediate, with no image scale or movement. No carousel, zoom/pan, download, or gallery autoplay.

## Engineering sequence

1. Capture settled P04 geometry and screenshots at 320, 390, 768, 1024, and 1440px, plus no-JS and reduced-motion states.
2. Add motion-role attributes or narrowly scoped wrappers to `index.html` only where a true clip needs a separate layer. Do not change text, link targets, image mapping, reading order, or fixed geometry.
3. Implement P04-only custom properties and role selectors in `css/p04-home.css`; adjust shared `css/style.css` primitives only where necessary for the common observer, menu, focus, or lightbox. Maintain static CSS as the readable default.
4. Extend `js/script.js` only to map declarative roles, arm safe offscreen targets, and resolve all fail-open/focus/reduced/restoration cases. Retain finite IntersectionObserver work and disconnect/unobserve settled targets.
5. Update `scripts/qa-m1.py` and `scripts/qa-static.py` for exact content, one-time completion, the new section timing ranges, absence of pending content and idle animations, reduced motion, no-JS, missing IntersectionObserver, focus, menu, and lightbox. Run the existing browser suite and inspect screenshots on desktop and mobile.

Expected implementation files: `index.html`, `css/p04-home.css`, `js/script.js`, `scripts/qa-m1.py`, and possibly `css/style.css`, `scripts/qa-static.py`, `README.md`, and this plan/report if shared primitives or documentation need updating. No Cloudflare or domain file is in scope.

## Acceptance risks to check

- Long text and the corrected Tahfizh label must fit the existing P04 composition at 320–1440px; content correction must not induce overlap, overflow, or a hidden value.
- Clip paths and large translation must not crop focused controls, glyph descenders, photo captions, or the overlay lightbox button. Do not move layout boxes or create CLS.
- Tall sections, fast scrolling, anchor jumps, browser restoration, and late JavaScript must not leave content pending. No reveal should replay after it settles.
- Mobile sequences must complete near the section being read, without making later cards wait for earlier offscreen cards. Safe-area and short-viewport dialog/menu behavior remain usable.
- Reduced motion removes substantial translation, clipping, scaling, and choreography, including live preference changes. Screen-reader reading order, keyboard access, visible focus, and native links remain independent of animation.
- Inspect main-thread cost on modest mobile hardware: animate transform/opacity/contained clip sparingly, avoid broad `will-change`, and leave no active animations or observers tracking completed reveal targets.
- Check selector direction when implementing P04 overrides: M1 adds `motion-ready` to `<html>`, while the current `css/p04-home.css` rule `.p04 .motion-ready .pillars > .container::before` expects it below the P04 body and therefore cannot match. Correct the selector during motion implementation, with a settled-state visual comparison.
